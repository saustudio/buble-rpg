# Спецификация архитектуры системы статов (v3.0)

## 1. Общие принципы

### 1.1 Разделение ответственности
- **Модели данных** (Item, EntityStats, EquipmentComponent) - только хранение данных, без логики
- **Фабрики** (ItemFactory) - создание и первичный расчет объектов
- **Системы** (EntityStatsSystem) - расчеты на основе данных из компонентов
- **UI** - отображение данных без их модификации

### 1.2 Иерархия данных
Сбор данных -> Применение модов по названиям -> Итоговые статы -> Использование

### 1.3 Принципы расчетов
- Все расчеты выполняются в системах, модели данных не содержат логики
- Каждый предмет имеет три типа аффиксов: Base (базовые), Implicits (встроенные), Explicits (случайные)
- LOCAL_* аффиксы изменяют сам предмет и применяются на этапе создания
- Глобальные аффиксы влияют на персонажа и применяются в EntityStatsSystem
- **Каждый мод применяется по своему уникальному названию, без попыток категоризации**
- **Каждый стат рассчитывается отдельно, со своей уникальной логикой**

## 2. Модели данных

### 2.1 Item
Назначение: Хранит все данные о предмете

Поля:
- Base: Map<string, number> - базовые свойства предмета (оригинальные значения)
- Explicits: Map<string, number> - случайные аффиксы (префиксы/суффиксы)
- Implicits: Map<string, number> - встроенные аффиксы (всегда присутствуют)
- Final: Map<string, number> - итоговые свойства предмета (с учетом LOCAL_*)
- Name, Level, Str, Dex, Int, Rarity, Class, Tag, Icon - метаданные
... и т.п.

Требования:
- Не содержит методов расчета
- Все Map доступны для чтения и записи
- Final заполняется только в фабрике

### 2.2 EquipmentComponent
Назначение: Контейнер для экипированных предметов

Поля:
- Weapon: Item | null
- Body: Item | null
- Helm: Item | null
- Gloves: Item | null
- Boots: Item | null
- OffHand: Item | null
- RingLeft: Item | null
- RingRight: Item | null
- Amulet: Item | null
- Belt: Item | null
... и т.п.

Требования:
- Не содержит расчетов
- Только хранение ссылок на предметы
- Все поля могут быть null

### 2.3 EntityStats
Назначение: Хранит итоговые статы персонажа

Поля (все статы - простые поля без вложенности):
- Life: number
- Mana: number
- Armour: number
- Evasion: number
- EnergyShield: number
- PhysicalDamageMin: number
- PhysicalDamageMax: number
- FireDamageMin: number
- FireDamageMax: number
- ColdDamageMin: number
- ColdDamageMax: number
- LightDamageMin: number
- LightDamageMax: number
- AttackSpeed: number
- MovementSpeed: number
- CriticalChance: number
- CriticalMultiplier: number
- Accuracy: number
- Range: number
- DamagePerSecond: number (производная)
- EffectiveHealth: number (производная)
- ChanceToHit: number (производная)
... и т.п.

Требования:
- Не содержит методов расчета
- Все поля доступны для чтения и записи
- Все поля пересчитываются заново при каждом обновлении

## 3. Слой создания (Factory)

### 3.1 ItemFactory
Назначение: Создание предметов с полным расчетом их свойств

Этапы создания предмета:
1. QueryBaseItem - выбор базового предмета из базы
2. CreateItem - создание экземпляра Item
3. ApplyBaseProperties - заполнение Base свойствами из базы
4. ApplyImplicits - добавление встроенных аффиксов
5. ApplyExplicits - добавление случайных аффиксов
6. ApplyFinals - расчет итоговых свойств

Правила расчета ApplyFinals:
1. Копирование Base во временную копию
2. Применение LOCAL_* модов к копии Base
3. Копирование измененной копии в Final
4. Добавление Implicits к Final (суммирование с существующими)
5. Добавление не-LOCAL_* Explicits (только если ключа нет в Final)

LOCAL_* аффиксы и их влияние:
- LOCAL_PHYSICAL_DAMAGE_INC -> увеличивает физический урон (умножение)
- LOCAL_ARMOUR_INC -> увеличивает броню (умножение)
- LOCAL_EVASION_INC -> увеличивает уклонение (умножение)
- LOCAL_ES_INC -> увеличивает энергощит (умножение)
- LOCAL_FIRE/COLD/LIGHT_DAMAGE_MIN/MAX -> добавляет стихийный урон (сложение)
- LOCAL_ARMOUR_ADD -> добавляет броню (сложение)
... и т.п.

Требования:
- Единственное место создания предметов
- Все расчеты свойств предмета выполняются здесь
- Порядок вызовов строго соблюдается
- Сложные модификаторы создаются только для известных аффиксов

## 4. Слой расчетов (Systems)

### 4.1 EntityStatsSystem
Назначение: Сбор и расчет всех статов персонажа

Принцип работы:
- Для каждого стата своя уникальная логика расчета
- Сбор плоских значений из всех источников
- Сбор модов по их названиям
- Применение каждого мода по его названию через switch/case
- Неизвестные моды логируются, но не ломают систему

### 4.2 Расчет каждого стата

Общий алгоритм для каждого стата:
1. Собрать все плоские значения из всех источников
2. Собрать все моды, влияющие на этот стат (по названиям)
3. Применить каждый мод по его названию (уникальная логика)
4. Сохранить финальное значение в EntityStats

Пример для Life:

1. Сбор плоских значений:
   - HealthComponent.Base
   - ExpComponent (Lvl * 10)
   - item.Final.LIFE_MAX (из всей экипировки)

2. Сбор модов для Life:
   - item.Explicits.life_increase_%
   - item.Explicits.life_more_%

3. Применение каждого мода по названию:
   - life_increase_%: life *= (1 + value / 100)
   - life_more_%: life *= (1 + value / 100)
   - life_to_armour_%: конвертация жизни в броню
   - life_if_low_%: условное увеличение

### 4.3 Источники данных

Для плоских значений:
- HealthComponent -> Life
- ExpComponent -> Life, PhysicalDamage
- item.Final -> все свойства (Armour, PhysicalDamage, AttackSpeed и т.д.)
- SkillTreeComponent (TODO) -> все статы
- BuffComponent (TODO) -> все статы
... и т.п.

Для модов:
- item.Explicits -> все глобальные аффиксы
- SkillTreeComponent (TODO) -> моды от дерева навыков
- BuffComponent (TODO) -> моды от баффов
... и т.п.

### 4.4 Обработка модов

Принцип обработки:
- Каждый мод имеет уникальное название (ключ)
- Алгоритм применения определяется по названию
- Неизвестные моды логируются с предупреждением

Пример:
if(key=='life_increase_%')   life *= (1 + value / 100);
if(key==`conversion_physical_to_cold_%`) damage *= (1 - value / 100);
... и т.п. 
или Logger.Warn(`Неизвестный мод: ${key}`);

### 4.5 CalculateDerivedStats
Производные статы:
- DamagePerSecond = (средний урон) * AttackSpeed
- EffectiveHealth = Life / (1 - DamageReduction)
- ChanceToHit = функция от Accuracy и других факторов

## 5. Поток данных

### 5.1 Создание предмета

ItemFactory.Random()
1. QueryBaseItem - выбор базы
2. CreateItem - создание экземпляра
3. ApplyBaseProperties - заполнение Base
4. ApplyImplicits - заполнение Implicits
5. ApplyExplicits - заполнение Explicits
6. ApplyFinals - расчет Final

### 5.2 Расчет статов персонажа

EntityStatsSystem.Update()
1. Для КАЖДОГО стата:
   a. Собрать все плоские значения
   b. Собрать все моды по названиям
   c. Применить каждый мод по его названию
   d. Сохранить в EntityStats
2. Рассчитать производные статы
3. Обновить Version

### 5.3 Использование статов

Системы-потребители используют простые поля EntityStats
- MovementSystem -> stats.MovementSpeed
- AttackSystem -> stats.PhysicalDamageMin / PhysicalDamageMax
- HealthSystem -> stats.Life
- DefenceSystem -> stats.Armour
- UISystem -> stats.Life, stats.Armour, stats.DamagePerSecond и т.д.

## 6. Ключевые правила

### 6.1 Что НЕЛЬЗЯ делать
- Модели данных не должны содержать методов расчета
- Пытаться категоризировать все моды (increase/more/conversion)
- Создавать универсальные структуры для всех модов
- Изменять исходные данные предмета после создания
- EntityStats НЕ должен содержать вложенных объектов

### 6.2 Что МОЖНО делать
- Добавлять новые моды
- Иметь уникальную логику для каждого мода
- Логировать неизвестные моды для будущей реализации
- Добавлять новые источники статов
- Иметь уникальную логику расчета для каждого стата

### 6.3 Принцип постепенного внедрения
- Начинаем с базовых модов (LIFE_MAX, LIFE_REGEN и т.д.)
- Сложные моды добавляем по мере необходимости
- Неизвестные моды игнорируем с логированием
- Каждый новый мод тестируем изолированно

---

## 7. Расширяемость

### 7.1 Добавление нового мода
1. Добавить название мода в нужный метод сбора (GetLifeMods, GetArmourMods и т.д.)
2. Добавить обработку в соответствующем методе применения (ApplyLifeMods и т.д.)
3. Реализовать уникальную логику в новом if/case/... и т.п.
4. Протестировать изолированно

### 7.2 Добавление нового стата
1. Добавить поле в EntityStats
2. Создать методы сбора плоских значений (GetXxxFromEquipment, GetXxxFromSkills)
3. Создать метод сбора модов (GetXxxMods)
4. Создать метод применения модов (ApplyXxxMods)
5. Добавить вызов в Update
6. Добавить в расчет производных (если нужно)

### 7.3 Добавление нового источника данных
1. Добавить метод сбора плоских значений из нового источника
2. Добавить метод сбора модов из нового источника
3. Интегрировать в существующие методы сбора

## 9. Список известных аффиксов

### 9.1 Базовые аффиксы (EAffixBaseType)
- BASE_ATTACK_TIME - время атаки
- BASE_CRITICAL_CHANCE - шанс критического удара
- BASE_PHYSICAL_DAMAGE_MIN - минимальный физический урон
- BASE_PHYSICAL_DAMAGE_MAX - максимальный физический урон
- BASE_RANGE - радиус атаки
- BASE_EVASION - уклонение
- BASE_ES - энергощит
- BASE_ARMOUR - броня
- BASE_MOVEMENT_SPEED - скорость движения


### 9.2 Эксплицитные аффиксы (EAffixExplicitType)

LOCAL_* аффиксы (влияют на предмет):
- LOCAL_PHYSICAL_DAMAGE_INC - увеличение физического урона (%)
- LOCAL_PHYSICAL_DAMAGE_REDUCTION_INC - увеличение брони (%)
- LOCAL_EVASION_INC - увеличение уклонения (%)
- LOCAL_ES_INC - увеличение энергощита (%)
- LOCAL_ATTACK_SPEED_INC - увеличение скорости атаки (%)
- LOCAL_CRITICAL_CHANCE_INC - увеличение шанса крита (%)
- LOCAL_FIRE_DAMAGE_MIN - минимальный огненный урон
- LOCAL_FIRE_DAMAGE_MAX - максимальный огненный урон
- LOCAL_COLD_DAMAGE_MIN - минимальный холодный урон
- LOCAL_COLD_DAMAGE_MAX - максимальный холодный урон
- LOCAL_LIGHT_DAMAGE_MIN - минимальный урон молнией
- LOCAL_LIGHT_DAMAGE_MAX - максимальный урон молнией
- LOCAL_PHYSICAL_DAMAGE_REDUCTION - добавление брони

Глобальные аффиксы (влияют на персонажа):
- LIFE_REGEN - регенерация здоровья
- LIFE_KILL - здоровье за убийство
- LIFE_MAX - максимальное здоровье
- PHYSICAL_DAMAGE_MIN - минимальный физический урон
- PHYSICAL_DAMAGE_MAX - максимальный физический урон
